\section{Experiments}
\label{sec:experiments}

This section reports the final V3 evaluation after the training protocol, hyperparameter schedule, and TensorBoard-backed logging pipeline were stabilized. The goal is to answer two questions. First, does cross-residual information flow provide a consistent benefit over plain stacking? Second, when compared against simpler residual reuse, where does the cross design help and where does it fail?

\subsection{Experimental Settings}

We begin with the shared protocol, because the later biological interpretation is only meaningful if model, data, and optimization choices are controlled consistently.

\subsubsection{Model Set}

We compare five architectures under the same \texttt{GCNConv} message-passing backbone:
\begin{enumerate}
    \item \textbf{PlainGNN}: plain stacked propagation without explicit hidden-state reuse
    \item \textbf{NodeResGNN}: single-branch node-level residual reuse
    \item \textbf{NodeCrossGNN}: two-branch node-level cross residual exchange
    \item \textbf{GraphResGNN}: graph-level residual refinement driven by pooled graph summaries
    \item \textbf{GraphCrossGNN}: graph-level cross residual exchange across consecutive block pairs
\end{enumerate}

This comparison isolates the effect of information-flow design while holding the operator family fixed.

\subsubsection{Dataset Scope}

The revised topic-facing discussion centers on the unified biological package introduced in Section~\ref{sec:datasets}:
\begin{itemize}
    \item \textbf{Main biological package}: PROTEINS, DD, ENZYMES
    \item \textbf{Supplementary biological or chemical datasets}: MUTAG, AIDS, Mutagenicity
\end{itemize}

This revised package separates the protein-oriented main narrative from supplementary robustness evidence and removes the earlier out-of-scope control dataset from the main text.

\subsubsection{Data Protocol}

With the benchmark scope fixed, we next define the common evaluation procedure applied to every completed run.

All reported results use stratified 5-fold graph-level evaluation. Inside each training fold, we construct a stratified validation subset with validation ratio 0.1. Model selection is based on validation loss, and the best checkpoint is evaluated on the held-out test fold.

This protocol replaces the earlier weaker contiguous fold slicing used during exploratory runs. The stratified design matters because it reduces majority-class collapse and exposes architectural differences more reliably.

\subsubsection{Optimization}

Once the split protocol is fixed, the remaining source of variation is the training configuration itself.

All runs use Adam, validation-based early stopping, \texttt{ReduceLROnPlateau}, and gradient clipping. The shared defaults are:
\begin{itemize}
    \item batch size = 32
    \item gradient clipping norm = 2.0
    \item scheduler factor = 0.5
    \item scheduler patience = 15
    \item minimum learning rate = $10^{-5}$
\end{itemize}

Plain and residual baselines use a common configuration:
\begin{itemize}
    \item epochs = 200
    \item patience = 60
    \item learning rate = 0.005
    \item weight decay = $10^{-4}$
    \item dropout = 0.5
    \item hidden dimension = 64
    \item hidden layers = 4
\end{itemize}

Cross-residual models use the stronger cross-specific V3 protocol:
\begin{itemize}
    \item default cross setting: epochs = 240, patience = 80, learning rate = 0.003, weight decay = $5\times 10^{-5}$, dropout = 0.3, hidden dimension = 64, hidden layers = 4
    \item PROTEINS / NodeCrossGNN: dropout = 0.2
    \item DD / NodeCrossGNN: hidden layers = 3
    \item DD / GraphCrossGNN: learning rate = 0.002, dropout = 0.2
\end{itemize}

\subsubsection{Reproducibility}

These settings are paired with a reproducible execution path so that the reported benchmark trends can be regenerated from stored artifacts rather than from hand-copied notes.

All final runs were executed with the same V3 code path, stratified 5-fold evaluation, and deterministic seed control. The experiments were run on a single NVIDIA RTX 3090 GPU with 24GB memory. Each completed run writes a structured JSON summary to the project \texttt{logs/} directory, and optional TensorBoard traces are written to \texttt{runs/}. The repository also includes batch execution, dataset-statistics export, summarization, and report-generation scripts so that the final tables in this paper can be regenerated directly from the stored experiment outputs.

\subsection{Main Findings}

These aggregate results already suggest the central pattern, which can be stated more directly before examining the protein-oriented datasets one by one.

\textbf{Residual reuse remains the strongest default family in the completed archive.} Residual variants win PROTEINS, DD, ENZYMES, and AIDS. This makes residual reuse the safest default baseline under the stabilized protocol. In particular, GraphResGNN is best on PROTEINS ($0.7223 \pm 0.0367$), ENZYMES ($0.3117 \pm 0.0746$), and AIDS ($0.9160 \pm 0.0121$), while NodeResGNN is best on DD ($0.7207 \pm 0.0259$).

\textbf{Cross-residual design is selectively strong, not universally dominant.} Cross variants still win completed datasets such as MUTAG and Mutagenicity. More importantly, the best cross variant beats PlainGNN on most completed datasets. Therefore, cross routing is clearly more than an implementation curiosity: it is a useful alternative information-flow mechanism. However, it still does not consistently beat the best residual baseline, so the evidence does not support the stronger claim that cross universally outperforms residual reuse.

\textbf{Node-level cross is more reliable than graph-level cross.} Across the completed datasets, NodeCrossGNN outperforms NodeResGNN more often than GraphCrossGNN outperforms GraphResGNN. This suggests that exchanging intermediate node-level states is the more robust cross-residual design in the present implementation, while graph-level cross routing is more dataset-sensitive.

\textbf{Plain stacking is no longer a credible final baseline.} PlainGNN remains competitive on PROTEINS and DD, but it never wins a dataset in the final suite and is usually surpassed by either a residual or a cross-residual variant. This is important for the paper narrative: the meaningful comparison is no longer cross versus plain, but cross versus the stronger residual family.

\subsection{Topic-Facing Biological Interpretation}

The full-suite pattern is still methodologically useful, but the topic-facing interpretation should be anchored in the protein-oriented core datasets. In that narrower sense, the strongest evidence comes from PROTEINS, DD, and ENZYMES, because they are the closest proxies in the current paper to protein- and enzyme-centered functional inference.

On \textbf{PROTEINS}, GraphResGNN is clearly strongest, indicating that repeated graph-level residual refinement is the most effective way to preserve useful global structure. The best cross model here is NodeCrossGNN at $0.6972 \pm 0.0430$, which improves slightly over NodeResGNN but remains below both PlainGNN and GraphResGNN.

On \textbf{DD}, NodeResGNN and NodeCrossGNN are nearly tied, with NodeResGNN retaining a narrow lead. This indicates that node-level hidden-state reuse is important on large sparse protein graphs, but cross exchange does not produce a decisive improvement over simpler residual reuse.

On \textbf{ENZYMES}, cross variants become more attractive. GraphCrossGNN reaches $0.3017 \pm 0.0750$ and NodeCrossGNN reaches $0.3000 \pm 0.0580$, both clearly above PlainGNN at $0.2450 \pm 0.0407$. Even so, GraphResGNN still remains the best model. Therefore, ENZYMES is the cleanest topic-facing dataset for arguing that cross-residual pathways can recover useful information that plain stacking loses, but not for arguing that cross should replace residual baselines outright.

\subsection{Ablation Conclusions}

Taken together, these dataset-level observations can now be condensed into a single ablation message.

The final ablation story is therefore precise:
\begin{itemize}
    \item \textbf{Plain $\rightarrow$ Cross}: cross-residual routing is usually beneficial relative to plain stacking
    \item \textbf{Residual $\rightarrow$ Cross}: the gain is conditional and dataset-dependent
    \item \textbf{Node-level versus graph-level}: node-level cross is more stable, while graph-level cross achieves stronger wins only on selected datasets
\end{itemize}

This is the strongest claim that the current evidence supports. Cross-residual design should be presented as a meaningful and reusable architectural design space, not as a universal winner over residual reuse.

\subsection{Parameter Sensitivity}

The next question is whether this ablation story is stable under moderate changes in the cross-model hyperparameters.

To complement the structural ablation, we ran a focused parameter scan for the two cross-residual models on the topic-facing datasets PROTEINS, DD, and ENZYMES. The scan varies depth ($h \in \{3,4,5\}$), dropout ($\{0.2,0.3,0.5\}$), and learning rate ($\{0.002,0.003,0.005\}$) on fold 0 while keeping the stabilized V3 training protocol fixed. The sensitivity patterns are dataset-specific rather than uniform. On \textbf{PROTEINS}, NodeCrossGNN is most sensitive to depth, with the three-layer configuration outperforming the deeper alternatives, while GraphCrossGNN benefits from lighter dropout. On \textbf{DD}, both cross variants are more optimization-sensitive: larger learning rates help, and GraphCrossGNN is especially sensitive to depth, where the three-layer setting is substantially better than four layers. On \textbf{ENZYMES}, however, the scan exposes a different regime. Many runs obtain the best validation loss at or near the first epoch, which indicates that the small validation split is too noisy to provide a reliable tuning signal.

To verify whether the ENZYMES fold-0 hints were actionable, we ran a 5-fold tuned follow-up with the most promising settings from the scan. The tuned NodeCrossGNN setting ($h=3$, drop$=0.2$, lr$=0.003$) reaches $0.2767 \pm 0.0698$, and the tuned GraphCrossGNN setting ($h=3$, drop$=0.2$, lr$=0.002$) reaches $0.2917 \pm 0.0675$. Both remain below the original full-suite ENZYMES cross results, so we do not replace the main table with the tuned numbers. Instead, the follow-up supports a more careful interpretation: on the smallest dataset, validation noise can dominate local hyperparameter gains, and apparent fold-level improvements do not necessarily transfer to the 5-fold mean.

\subsection{Analysis Assets}

Beyond accuracy tables and sensitivity plots, the pipeline also records auxiliary evidence that helps interpret why certain runs succeed or fail.

To support interpretation beyond scalar accuracy, the current V3 pipeline records:
\begin{itemize}
    \item TensorBoard traces for loss, accuracy, learning rate, gradient norm, embedding norms, and logit statistics
    \item exported artifacts for graph embeddings, logits, predictions, and confusion-matrix reconstruction
    \item per-fold JSON logs containing parameter counts, optimization trajectories, and best-epoch summaries
\end{itemize}

These materials make it possible to distinguish genuine structural gains from accidental improvements caused by unstable training dynamics.

\subsection{Current Limitations}

These analysis assets help bound the claims, but they do not remove the core scope limitations of the current study.

The experiments remain structure-centric rather than fully omics-integrative. Accordingly, the strongest defensible claim of the paper is that CR-GNN is an effective biomolecular graph representation architecture with dataset-dependent cross-residual gains. The current evidence does not yet justify a broader claim about integrative omics prediction or direct discovery of novel genes, domains, or motifs, but the revised benchmark package still has a clear extension path toward plant-related graph inference settings.
